# 石桥纹样改造方案（素雅文人园档）

> 状态：**已实施**（2026-10-30）。实施中与原方案的偏差见 §6。
> 坐标基准（`Y0 = 0`，b 档 rise 3.2）：`X0 = 10`、`ZC = 16`、`HALF = 11`、`HW = 1.8`、
> `WATER = -0.55`、`BOTTOM = -1.70`、`YRING = -0.45`、`R_IN = 2.69`、`R_OUT = 3.15`、
> 桥面 crown `y = 3.20`、桥面净宽 `pw = 3.17`、`zEndN = 5.05`、`zEndS = 26.95`。
> 定档：A 素雅文人园 / 矢高 b 档 3.2 / 桥心石六旋水纹 / **全桥不刻任何文字**（桥联、桥额均已删除）。

## 0. 已裁决：b 档，矢高 5.4 → 3.2

### 为什么必须改

`src/layout.js:114` 原为 `rise: 5.4`，注释「steep humpback like 玉带桥」；而 `REFACTORING_PLAN.md`
P0-15 要求「收敛为矢高 1.55 m 的江南青石平拱桥」——二者冲突，说明 P0-15 的形制整改已被回退。

更硬的理由不是风格，而是**剖面不可用**：按 `bridge.js` 的 crown-arc + 直坡求解，
`rise = 5.4` 时切点 `thT ≈ 1.0405 rad`，直坡坡度 `slopeT = tan(thT) ≈ 1.72`，即 **60°**，人无法行走；
改为 `rise = 3.2` 后 `thT ≈ 0.307 rad`，坡度 **0.317（17.6°）**，是正常石桥坡道。

### 参数对照（rise 5.4 → 3.2）

| 参数 | 原（5.4） | 现（3.2） | 备注 |
|---|---|---|---|
| `layout.js:114` rise | 5.4 | **3.2** | 注释已改「江南青石拱桥」 |
| deck crown arc `RC` | 7.0 | 7.0 | `min(7.0, HALF*0.95)` |
| 切点 `thT` | 1.0405 rad（59.6°） | **0.307 rad（17.6°）** | 二分求解 |
| `zT` / `yT` | 6.04 / 1.94 | **2.15 / 2.87** | 拱弧段与直坡段分界 |
| 直坡坡度 `slopeT` | 1.72（60°） | **0.317（17.6°）** | 关键改善 |
| `R_IN` | 4.62 | **2.69** | 由拱肩反解 |
| `R_OUT` | 5.08 | **3.15** | `R_IN + 0.46` |
| `YRING` | −0.45 | −0.45 | `WATER + 0.10` |
| 拱顶内弧 / 外弧 | 4.17 / 4.63 | **2.24 / 2.70** | |
| 拱洞净跨 / 净高 | 9.24 / 4.72 | **5.38 / 2.79** | 拱券矢跨比 0.52，半圆陡拱 |
| 拱肩（拱顶外弧→桥面） | 0.77 | **0.50** | 容纳眉石与填土 |
| 踏步 | 64 级 | 30 + 平台 + 30 级 | 拱顶让出 1.20 m 平台 |

口径：桥面高跨比 = 3.2 / 22 = 0.145；拱券矢跨比 = 2.79 / 5.38 = 0.52。前者是"路"、后者是"洞"——
江南石拱桥正是**路面平缓、洞门高敞**这一组合。

### 改法（已落地）

1. `src/layout.js:114`：`rise: 5.4` → `rise: 3.2`，注释改为江南青石拱桥。
2. `src/world/bridge.js` 的券圈半径改为**由拱肩余量反解**，使矢高可调而券圈自动跟随：

   ```js
   const YRING = WATER + 0.10;
   const R_OUT = Math.max(1.0, (Y0 + RISE - 0.50) - YRING);   // 拱肩留 0.50
   const R_IN  = Math.max(0.55, R_OUT - 0.46);                // 券厚 0.46
   ```
3. 自动跟随的部分：金刚墙（用 `rMid`）、`wallBaseY()`（用 `R_OUT`）。
4. **镜头复核结果：`shots.js` 无需改动** —— 全片 10 组镜头里没有"站在桥面上"的机位，
   受影响的只是桥在远景中的高度。`bridge.js` 的 `showcase` 视角已按新 crown 3.2 重写并补了 3 个特写。

### 纹样依据（考据）

- 《苏州明清古桥石作艺术特征探究》：栏板正背两面雕桥名、桥联、修建年代，并雕**如意、定胜、莲瓣**等吉祥图案；望柱雕立体狮首或嵌抱鼓石。
- 武康宋元石桥：**望柱柱头雕刻仰覆莲瓣纹**（浙江日报）。
- 吴江黎里青龙桥：**柱头刻覆莲纹式**；桥身两侧嵌武康石**龙首**；**桥面有轮回纹饰**。
- 嘉定古桥群：桥心石为**双卷云六旋水纹**；**龙门石**位于拱圈顶端；**长系石（桥耳）**明以前多用**莲花纹**。
- 宜兴古桥：望柱柱头**方头式与莲瓣式**；**抱鼓石**饰折枝花如意纹、太极阴阳鱼；雕刻见于桥栏、望柱、长系石、抱鼓石、龙门石、拴船石。
- 宁波上升永济桥：桥心石圆框内莲荷 + 鹭鸟；拱顶龙门券「鲤鱼跳龙门」；**匾式桥额嵌于中栏外侧的拱券之上**。

**共同底色：图必有意、意必吉祥，但一律压地隐起浅浮雕，几无真镂空。**

## 2. 纹样规格（已实施）

统一原则：几何只做"大形"，细部纹样走 shader 的 `g_h` 高度通道 + bump，与项目既有的「瓦片由单片挤出降为凹凸贴图」策略一致。

### 2.1 石材色：中性灰 → 水磨青石（做法与初版方案不同）

实测结论：本场景的夕照曝光把 0.25 以上的反照率**全部推到 ACES 高光肩部**，单压 tint 视觉上几乎无差
（0.82 → 0.34 肉眼分辨不出；用极端值 0.02 验证过 uniform 通路是通的）。最终走三步：

| 手段 | 实现 | 作用 |
|---|---|---|
| 反照率 + 色相 | tint `vec3(0.62, 0.70, 0.685)` | G 最高、B 略高于 R，中性偏冷的石色底 |
| 暗部冷调 | `fragLight`：按亮度 `kF` 把 `directDiffuse` / `indirectDiffuse` 往 `vec3(0.84, 0.99, 1.05)` 偏 | 青灰只在**暗面**读出来 —— 真实青石就是这个行为 |
| 直射压制 | `fragLight`：`directDiffuse *= 0.38` | 迎光面从象牙白落到浅灰，不再和白粉墙撞在同一个高光肩 |

- `materials.js` 的 base 不动（`PROC.limestone` 仅 bridge 使用）。
- ⚠️ 若将来调整**全局曝光**（`env.js` / `sky.js`），0.38 与暗部冷调必须重新标定。
- 已清注释：`materials.js` 头部、bridge.js 头部与全部「玉带桥」→ 江南青石拱桥。

### 2.2 栏板：透雕 → 实心 + 如意云头开光（已实施）

- 删除 `commaHole` 云钩透雕，改实心青石板。
- 每 bay 一块梯形板，由两层构成：
  - **内板**（整块）：正面退到 `+0.0185`；
  - **外框**（带开光洞，厚 8 mm，`0.020~0.028`）：比内板凸出 9.5 mm，形成"压地隐起"的开光边框。
  - 内板正面与边框背面留 1.5 mm 缝 —— 共面会 z-fighting（实测就是竖向条纹的来源）。
- **如意云头**：三卷云极坐标轮廓（`cloudOutline`），随桥面坡度斜置（`skew`），凸 12 mm。
- 关键坑：开光洞的四角必须跟栏板一起随坡度倾斜。用水平矩形会在斜板上越出板边、三角化出错。

### 2.3 望柱头：云蕾 → 仰覆莲瓣（已实施，P0-10）

- 宋式：下仰莲 8 瓣 + 束腰 + 上覆莲 8 瓣 + 顶心收尖。
- 做法：`LatheGeometry`（32 段）生成母体后，用 `petalize()` 沿周向按 `cos(8θ)` 调半径出瓣脊。
- **踩过的坑**：振幅 0.24 会变成"齿轮/飞碟"（横向锯齿）；收敛到 **0.07** 才是莲瓣的浅竖棱。
- 尺寸：总高 0.17，最大径 0.164（端柱 ×1.35）。

### 2.4 桥心石：拱顶平台 + 六旋水纹（已实施）

- 拱顶 `|z − ZC| ≤ 0.60` 改为平台，一整块石板，顶面 `y = 3.20`，坐在拱顶外弧（2.70）之上。
- 两端踏步各自取整（各 30 级），对齐平台边界，不出半级。
- 纹样**走 shader**：圆心 `(X0, ZC)`，**圆框直径 1.10**（初稿写的 1.90 有误 —— 平台沿桥向只有
  1.20 m 进深，圆放不下），框内六条绕心渐收的水涡 + 中心圆，凹刻 8~12 mm。

### 2.5 长系石 / 桥耳（已实施）

- 位置 `z = ZC ± (R_OUT + 0.35)` = 12.50 / 19.50，`y = WATER + 1.10`，从桥墙外皮挑出 0.38。
- 端面 0.36 × 0.36，浅浮雕**正面莲花 8 瓣**（同一套 `cloudOutline`，n=8），凸 10 mm。

### 2.6 抱鼓石（已实施）

- 鼓面加折枝花（六瓣，n=6）+ 一圈凸弦纹，两面都刻。

### 2.7 扶手石与术语（已实施）

- 寻杖断面圆角矩形 → 石作盝顶断面（0.115 主体 + 0.09 收分脊），更名扶手石/压顶石。
- **删除绦环**（宋式木勾栏构件，石桥无此件），栏板直接顶到扶手石下皮。
- 地栿保留。

### 2.8 删除桥联与桥额（已实施）

- 桥联整段移除。
- **桥额也一并删除**（用户看过「枕流」成图后决定不要）：拱券上方、栏杆外侧的桥墙恢复素面青石，
  `glyph()` 笔画系统与「枕流」字表全部移除。**全桥不刻任何文字。**
- 教训：程序化笔画拼汉字在 0.3 m 尺度上无论怎么做都像玩具字，近景经不起看；
  真桥的桥额靠的是书法水准，不是几何拼装。

## 6. 实施记录与遗留

**与原方案的偏差**

1. 石材色：初版"只改 tint"无效（ACES 高光肩），改为「tint + 暗部冷调 + 直射 ×0.38」三步。
2. 桥心石圆框直径 1.90 → **1.10**（平台进深 1.20，原数放不下）。
3. 桥心石与长系石的纹样**走 shader / 程序化轮廓**，未新增贴图或高面数雕件。
4. **桥额取消**：原定阴刻「枕流」，成图后判定程序化笔画在 0.3 m 尺度上像玩具字，整块删除。

**遗留**

- **web 端资产未同步**：`node tools/export-web-assets.mjs` 打包出 291 MB GLB 后
  `ERR_BLOB_OUT_OF_MEMORY` 上传失败（现有 `web/public/assets/gusu-garden-core.glb` 是 22 MB 的旧版）。
  这是既有的导出容量问题（全场景 4.34 M 面），不是本次改动引入 —— 需改成分块导出 / 流式上传，
  或对桥单独导出。**在修好之前，web 交互版看到的仍是旧桥。**
- 莲瓣柱头在极近特写下仍略偏"宝珠/葫芦"，瓣尖的方向感偏弱；如需更强，可在瓣尖高度加一层
  高斯窗口的 `y` 抬升（`petalize` 支持改为高斯窗）。
